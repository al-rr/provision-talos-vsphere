# talos-smoke

This project was originally generated by:

```bash
export PROJECT_DIR="$(pwd)/overlays/lab/talos/talos-smoke"
cluster.sh create-project --project-dir="$PROJECT_DIR"
```

Since Iteration 10, `cluster.sh` is a deprecated compatibility shim that
forwards to `cluster-toolchain.sh`, which has no local command-hook
indirection. Use `cluster-toolchain.sh` for any new command against this
project.

## Legacy Configuration Note

`vars.sh` in this project still sets the `TALOS_DAY1_*` mapped-command
variables listed below. They are **not read by anything in this repository's
active dispatch path** — that mechanism existed only in the old local
`cluster.sh`, which has been replaced with a pure forwarding shim. They are
left in place as a historical record of how this project was originally
configured, not as evidence of a still-used workflow:

- `TALOS_DAY1_GENERATE_CMD`
- `TALOS_DAY1_PROVISION_CMD`
- `TALOS_DAY1_PREPARE_BOOTSTRAP_CMD`
- `TALOS_DAY1_APPLY_CONFIG_CMD`
- `TALOS_DAY1_BOOTSTRAP_CMD`
- `TALOS_DAY1_SYNC_ACCESS_CMD`
- `TALOS_DAY1_MANIFEST_ROOT_DIR`
- `TALOS_DAY1_KUBE_CONTEXT`

`TALOS_CLUSTER_BASELINE_ADDONS` is unrelated to this and remains a live,
consumed variable.

See `overlays/base/scripts/talos/docs/CLUSTER_GUIDE.md` for the current
`cluster-toolchain.sh` contract, and the variable reference in the
`talos-toolchain` repository:

- `docs/en/day1-project-vars.md`
- `docs/pt-br/day1-project-vars.md`

Refresh schematics:

```bash
cluster-toolchain.sh refresh-schematics --project-dir="$PROJECT_DIR" --talos-version=v1.12.4
```
